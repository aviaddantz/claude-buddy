# Claude Buddy v19 — Menu Bar App

## What Changed from v18

The daemon had no persistent management UI. The only way to toggle, restart, or quit it was the terminal. v19 adds a native Swift menu bar app (`Nudge.app`) that sits in the menu bar and manages the daemon lifecycle, replacing the `SessionStart` hook with a proper Login Item.

---

## Changes

### 1. Swift menu bar app (NudgeApp/)
**Before:** No management UI. Daemon was started via `SessionStart` hook and could only be stopped from the terminal (`bash stop-daemon.sh`).
**After:** `Nudge.app` lives in `/Applications` and the menu bar. Provides Pause/Resume, Restart, Quit, and Launch at Login. The app polls `pgrep` every 2s and reflects daemon state in the menu label ("Active" / "Inactive").

### 2. Daemon startup moved to Login Item
**Before:** `SessionStart` hook in `~/.claude/settings.json` ran `start-daemon.sh` at the start of every Claude Code session.
**After:** `Nudge.app` starts the daemon on launch and registers as a macOS Login Item via `SMAppService`. The `SessionStart` hook for the daemon is removed.

### 3. Toggle behavior
**Before:** No toggle. `stop-daemon.sh` wrote a disable flag; re-enabling required manually deleting the flag.
**After:** Pause calls `stop-daemon.sh` (kills daemon + sets disable flag). Resume deletes the flag then calls `start-daemon.sh`. The flag deletion step is necessary because `start-daemon.sh` exits early if the flag exists.

### 4. Claude mascot app icon
**Before:** No app icon (default macOS generic icon).
**After:** `AppIcon.icns` generated by `make_icon.py` using PIL. Salmon body (`#D67E64`), white sticker border, dark pixel eyes, green rope — exact geometry from the `SpriteWidget` in `buddy.py`. Menu bar icon is a black template silhouette of the same mascot.

### 5. Python dock icon hidden
**Before:** `buddy.py` appeared as a Python app icon in the dock while running.
**After:** One line added to `buddy.py` after `QApplication` init: `NSApplication.sharedApplication().setActivationPolicy_(NSApplicationActivationPolicyAccessory)`. Daemon runs as a background accessory with no dock presence.

### 6. Build toolchain workaround
**Before:** N/A (no Swift code).
**After:** CLT 16.4 has a bug where `module.modulemap` and `bridging.modulemap` both define `SwiftBridging`, breaking all Swift compilation. Workaround: `fix-modulemap.yaml` is a VFS overlay that maps `module.modulemap` to `/dev/null`, passed to `swiftc` via `-vfsoverlay`. `bundle.sh` compiles via `swiftc` directly (SPM manifest compilation is also broken on this CLT version).

---

## What Stayed the Same

* `buddy.py` — floating chip, sprite, pill UI, approval flow, all untouched (except dock icon fix)
* `notify.sh` — unchanged, still the `PermissionRequest` hook entry point
* `classify.py` — risk classification unchanged
* `stop-daemon.sh` / `start-daemon.sh` — unchanged, called by the Swift app

## Known Issues (logged for v20)

* **Menu bar icon is a generic black silhouette** — the Claude figure is recognizable at large sizes but looks like a blob at 16px. A purpose-designed minimal template icon (e.g. just the head) would read better at small sizes.
* **Login Item registration requires /Applications** — `SMAppService` silently fails if the app is run from the dev directory. No error surfaced to the user.
* **No visual feedback when daemon is starting** — after clicking Resume/Restart, the status label says "Inactive" for ~2s while the daemon initializes. Could show a "Starting..." state.
* **`swift build` / `swift package resolve` broken on this machine** — CLT 16.4 bug. Any future Swift changes require `bash bundle.sh` directly, not standard SPM tooling.
* **Terminal approval delay** — (carried from v17) pill stays until tool completes.
